# Maintaining this profile

The page is the chart-recorder design: four SVG panels rendered daily from data,
followed by plain Markdown. The version before it lives on branch
`backup/profile-v1`.

## Layout

| # | Block | Source | Refresh |
|---|---|---|---|
| 1 | Nameplate + readouts | `assets/panel-nameplate{,-m}.svg` | daily |
| 2 | Intro, links, headline "N fixes landed upstream" | `README.md` | headline daily |
| 3 | Platform + code lanes | `assets/panel-lanes{,-m}.svg` | daily |
| 4 | Coding agents | `assets/panel-agents{,-m}.svg` | daily |
| 5 | Live per-project badges, three recent examples | `README.md` | badges live (shields.io); examples by hand |
| 6 | Notes to share | `assets/panel-cards{,-m}.svg` | when `data/profile.json` changes |
| 7 | Channel, footer | `README.md` | by hand |

Each panel is one desktop SVG (900 wide) and one mobile SVG (400 wide); the
README picks between them with `<picture>`.

## Daily workflow

`.github/workflows/upstream-count.yml` — 06:00 IST, and on demand from the
Actions tab:

1. `scripts/upstream-count.mjs` recounts from the GitHub search index, rewrites
   the headline only when the number changed (the date beside it is the last
   change), and writes `data/upstream-stats.json`.
2. `scripts/build-panels.mjs` renders the eight SVGs from
   `data/upstream-stats.json` + `data/profile.json`, rewriting a file only when
   its content changed.
3. Commits only if something changed. After 45 days without a commit it makes an
   empty keepalive commit (GitHub disables schedules after 60 days).

**Count definition.** Pull requests by `santhiprakash` with `is:merged` in
repositories **not** owned by `santhiprakash`, `minervainfo`, `minervainfoedtech`
or `santhiprakashb` — other people's projects only. Public repositories only:
that is all a visitor, and the workflow token, can see. To change the list, edit
`EXCLUDED_OWNERS` and run the workflow by hand.

**Source.** GitHub search, the same index as the shields.io badges. Do not count
with the list-pull-requests REST endpoint: it ignores `creator`.

## Hand-written content — `data/profile.json`

| Field | What it is | Rule |
|---|---|---|
| `tagline`, `title` | Nameplate lines | one short sentence each |
| `platform[]` | A lane: name, `state` (`on` / `off`), colour, `readings` (short lines), `events_by_month` | a lit lane needs evidence; record it in `evidence` |
| `agents[]` | Tool, `role` (`daily driver` / `fleet`), reading | `{named_tool.X}` is filled from what PR bodies disclose |
| `cards[]` | Symptom · cause · fix · takeaway | anonymise clients; name the upstream PR in the title |

Edit, run the workflow by hand (or `node scripts/build-panels.mjs`), commit.
Blips in a platform trace drop out when the six-month window passes them — add
`events_by_month` entries as incidents close.

## Measured daily vs. stated by you

- Measured: upstream merges, projects, submitted / open, merge rate, last 30
  days, per-month and per-language series, PR bodies that state AI assistance,
  named-tool counts (Cursor's marker, "AI: Devin", "Generated by Grok").
- Stated: platform readings and agent roles. Claude Code and Codex carry no
  counts because GitHub pull requests do not attribute them.

## Fonts

`assets/fonts/` holds subsetted OFL faces (Schibsted Grotesk, Spline Sans Mono),
embedded into every SVG as data URIs — GitHub shows SVGs through `<img>` and
never fetches external fonts. Rebuild only when the pinned google/fonts commit
changes or a panel needs new glyphs: Actions → **Build panel fonts** → Run
(`scripts/build-fonts.sh`; fonttools is installed in Actions, not on the
MacBook). Without the files the renderer falls back to system fonts.

## Previewing a redesign

Work on a branch, push, run the workflow on that branch; the profile page only
renders `main`. To publish:

```bash
git checkout main && git merge --ff-only <branch> && git push
```

To restore the previous design:

```bash
git checkout backup/profile-v1 -- README.md assets && git commit -am "revert: restore profile v1"
```
